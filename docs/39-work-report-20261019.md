# 서비스 보완 작업 결과

작성일: 2026-10-19

## 커밋과 작업 범위

기존 예매/환불/화면/검증 작업은 780b19f로 커밋하고 origin/main에 푸시했다. 이번 작업은 남아 있던 회원 관리, 참조 데이터 보호, 운행 취소, 운영 로그, 인증 응답, DB 마이그레이션과 실행 구성을 구현한다.

## 구현한 기능

### 회원 관리와 인증

- PATCH /api/users/me: 이름 변경. 이메일/권한은 변경할 수 없다.
- POST /api/users/me/password: 현재 비밀번호 검증 후 변경. BCrypt 입력은 최대 72 UTF-8 바이트다.
- POST /api/users/me/withdraw: 현재 비밀번호 검증 후 DELETED 처리. 활성 HOLD나 미래 확정 예매가 있으면 409, 관리자 일반 탈퇴는 403.
- 로그아웃/비밀번호 변경/탈퇴 시 tokenVersion 증가로 기존 모든 JWT를 무효화한다. 따라서 이번 버전 적용 전 발급된 토큰으로는 다시 로그인해야 한다.
- JWT 직접 문자열 파싱을 Nimbus JOSE/JWT 기반 HS256 검증으로 교체했다. 인증 실패는 401 AUTH_REQUIRED, 권한 부족은 403 ACCESS_DENIED JSON이다.
- 환경변수로 명시적으로 켤 때만 최초 관리자 생성. 기존 계정 승격/비밀번호 재설정은 하지 않는다.

### 예매 이력과 운행 취소

- Station→Route, Route→TrainSchedule, Train→Car/TrainSchedule, Car→Seat, Seat→ScheduleSeat 참조가 있으면 수정/삭제를 409로 막는다.
- 예매 이력이 있는 운행편은 시각/노선 변경과 삭제를 금지한다. 예약 없는 운행편은 생성된 좌석과 함께 삭제할 수 있다.
- 운행 취소 시 결제 대기 HOLD는 취소하고 확정 예매는 출발시각과 무관하게 전액 가상 환불한다. 한 트랜잭션으로 처리하여 일부만 반영되지 않게 한다.
- CANCELED/COMPLETED 운행편은 재개하지 않는다. 잘못 변경한 종료 상태는 새 운행편으로 등록한다.
- 운행편 공유 잠금 → Payment → 좌석 ID 순 잠금으로 신규 HOLD/결제와 관리자 취소를 직렬화한다. 운행 시간 중복 검사도 열차 잠금으로 직렬화한다.

### 운영 로그와 화면

- 로그인 실패, 회원 변경/탈퇴/로그아웃, HOLD/결제/만료/환불, 좌석 차단/해제, 운행 취소, 관리자 생성 이벤트 저장.
- 성공 로그는 해당 업무 트랜잭션과 함께 커밋하며 로그인 실패는 별도 트랜잭션에 기록한다.
- GET /api/admin/operation-logs: ADMIN만 접근, 이벤트/시작일/종료일/페이징 지원. 기본 최근 30일, size 1~100.
- 로그에 비밀번호/토큰/입력 이메일을 저장하지 않는다. 처리자 ID와 대상 ID 중심이다.
- 마이페이지 계정 관리와 관리자 운영 로그 화면을 구현하고 운행 취소 확인창을 연결했다.

### DB와 실행 구성

- Flyway V1/V2로 신규 DB 초기화 및 기존 DB baseline 이후 전환을 구현했다. Hibernate는 validate로 변경했다.
- 실제 로컬 DB는 스키마 백업 후 1:BASELINE, 2:SQL 적용을 확인했다. 기존 주요 테이블 행 수가 전후 동일했다.
- Docker 앱 전체 구성, Nginx API 프록시, 내부 관리용 health/Prometheus, Prometheus/Grafana 데이터 소스, k6 스크립트, CI 추가.
- 컨테이너 프론트는 8090, DB는 55432로 기존 로컬 실행 포트와 분리했다. DB/웹/모니터링 외부 공개는 기본 loopback 제한이다.

## 검증 결과

- 단위/실제 PostgreSQL/YAML 설정 검증 전체 89개 테스트 통과 (실패/오류/생략 0), 프론트 빌드 통과.
- 신규 DB V1→V2 및 기존 사용자 데이터 유지 baseline→V2 검증. 전체 기능 테스트도 Flyway 실제 스키마 + JPA validate로 수행.
- 운행 취소와 HOLD/결제 동시 실행, 확정/대기 예매 일괄 취소, 참조 데이터 삭제 방지, 예약 없는 운행편 삭제, 회원 변경/탈퇴/토큰 무효화, 운영 로그 권한/민감정보 비포함 검증.
- 브라우저에서 검색/HOLD/결제/환불, 이름 수정, 비밀번호 변경 후 재로그인, 회원 탈퇴, bootstrap 관리자 로그인, 운행 취소 자동 환불, 운영 로그를 확인했다. 1440px/390px 화면, JavaScript 오류 0.
- UI 검증 계정/데이터는 별도 스키마에서 수행 후 전부 정리했다. 실제 기존 계정의 권한/비밀번호는 변경하지 않았다.
- local health UP, Prometheus 응답 200 및 JVM 메트릭 확인.
- [GitHub CI 실행](https://github.com/seungheeHan777/railops/actions/runs/39264557742) 성공: Ubuntu/Java 21/PostgreSQL 16 테스트, 프론트 빌드, Compose 설정 검증, 백엔드/프론트 Docker 이미지 빌드. 초기 프론트 Dockerfile 커밋 누락은 392b897에서 수정했다.
- 같은 열차 운행편 동시 생성 충돌과 취소 운행편의 신규 대체 편성도 검증했다. 만료 토큰 401 응답 시 프론트 토큰 정리/로그인 전환은 별도 브라우저 응답 모의 테스트로 확인했다.
- 읽기 스모크: 동시 10개/총 200요청, 실패 0, 총 432ms, p50 11ms, p95 182ms, 최대 214ms. 같은 PC의 짧은 로컬 측정이며 production 성능이나 k6 실행 결과가 아니다.

## 아직 사용자의 환경이 필요한 부분

Docker가 설치되어 있지 않아 Compose 전체 서비스 실구동과 k6 컨테이너 장시간 부하는 로컬 미검증이다. 이미지 빌드 및 Compose 설정 검증은 GitHub CI에서 통과했다. 사용자가 Docker Desktop을 설치/실행하면 전체 서비스/모니터링/부하 검증을 이어갈 수 있다.

서버/도메인/TLS와 클라우드 배포 접근 정보가 없어 실제 서버 배포는 하지 않았다. 비용이 발생하는 리소스를 임의 생성하지 않았다.

## 남은 확장과 주의사항

- 실제 결제/환불, 부분 취소, 실서비스 요금/수수료, refresh token은 범위 밖이다. 현재 50,000원/전액 가상 환불 정책을 유지한다.
- 기준 데이터 참조 후 수정이 제한되어 기존 관리자 수정 동작에서 409가 나올 수 있다. 새로운 기준 데이터/운행편을 등록하는 방식으로 변경한다.
- 새 물리 좌석을 나중에 추가해도 이미 생성된 운행편의 좌석을 자동 보강하지 않는다. 필요한 편성을 먼저 만든 뒤 운행편을 등록한다.
- 운영 로그 보관기간/정리 배치, Grafana 대시보드·알람, 장시간·다중 서버 부하 검증은 후속 운영 작업이다.
- 일괄 운행 취소는 현재 단일 트랜잭션이다. 큰 운행편의 잠금 시간/트래픽은 운영 규모에 맞춰 배치 작업으로 확장할 수 있다.
- 회원 탈퇴는 계정 비활성화이며 개인정보 익명화/보존기간 정책을 자동 적용하지 않는다. 현재 예매 이력을 보존한다.
- local baseline은 편의를 위한 기존 DB 전환 옵션이다. 운영 DB에서는 백업/검토 후 명시적으로 설정한다. 적용된 마이그레이션 파일은 수정하지 않는다.
- .env는 Git에서 제외한다. .env.example의 예시 값은 운영 비밀번호/secret으로 사용하지 않는다.
