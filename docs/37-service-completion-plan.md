# 서비스 완성 작업 기준

작성일: 2026-10-19

## 구현 범위와 정책

- 기준 데이터는 다른 데이터가 참조하면 수정/삭제를 금지한다. Station→Route, Route→TrainSchedule, Train→Car/TrainSchedule, Car→Seat, Seat→ScheduleSeat 기준이다. 새로운 데이터를 등록하는 방향으로 이력을 보존한다.
- 예매 이력이 있는 운행편의 시각/노선 변경 및 삭제를 금지한다. 예약 없는 운행편은 좌석 행을 정리하여 삭제할 수 있다. CANCELED/COMPLETED는 종료 상태로 두며 재개하지 않는다.
- 운행 취소는 같은 트랜잭션에서 남은 HOLD 취소와 확정 예매 전액 가상 환불을 처리한다. 관리자 운행 취소에 따른 환불에는 사용자 출발 전 제한을 적용하지 않는다.
- 운행편 행 공유 잠금 → Payment → ScheduleSeat ID 순 잠금을 사용한다. 관리자 운행 변경/취소는 운행편 배타 잠금으로 신규 HOLD/결제와 직렬화한다.
- 회원은 이름 수정, 현재 비밀번호 확인 후 비밀번호 변경/탈퇴가 가능하다. 탈퇴는 데이터 삭제 대신 DELETED 상태로 전환한다. 활성 HOLD 또는 미래 확정 예매가 있으면 먼저 취소해야 한다. 관리자 계정은 일반 탈퇴를 금지한다.
- 비밀번호 변경/로그아웃/탈퇴 시 tokenVersion을 증가시켜 기존 JWT를 무효화한다. 로그아웃은 모든 기기의 토큰을 무효화하는 정책이다. refresh token은 후속 확장이다.
- 관리자 계정은 명시적인 환경변수로만 생성하는 bootstrap 기능을 제공한다. 기존 일반 계정을 자동 승격하거나 기존 관리자 비밀번호를 바꾸지 않는다.
- 예매/결제/환불/좌석 차단/회원 변경의 주요 이벤트를 트랜잭션과 함께 저장한다. 로그인 실패는 별도 트랜잭션으로 기록하되 비밀번호·토큰·입력 이메일을 로그에 저장하지 않는다.
- Flyway로 신규 DB 초기화와 기존 Hibernate DB의 baseline(버전 1) 이후 추가 마이그레이션을 검증한다. 기존 DB 적용 전 스키마만 백업하고, 데이터를 삭제하지 않는다.
- Docker/Nginx/Prometheus/Grafana와 CI/k6 구성을 추가한다. Docker/클라우드 자격정보가 없는 환경의 실제 배포는 완료로 표시하지 않는다.

## 검증

PostgreSQL 격리 스키마에서 신규/기존 DB 마이그레이션, 회원 관리/JWT 무효화, 운영 로그 권한, 참조 데이터 보호, 운행 취소 환불 및 동시 HOLD/결제 경합을 검증한다. React 타입 검사/빌드와 데스크톱/모바일 화면을 확인한다. 결과는 작업 보고서와 TODO에 기록한다.
